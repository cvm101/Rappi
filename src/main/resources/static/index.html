Purchasing Agent

Investigates with tools → decides → acts → validates its own result — like a human buyer

AI demo · sandboxed data
What is this? How does the agent work?

This demo replaces a buyer at a quick-commerce company. The buying system suggests an order (e.g. “buy 800 units”), but the suggestion is not always right. The agent checks it against real data and acts — safely.

1
InvestigateAn LLM calls read-only tools: inventory, open POs, supplier terms, budget, storage. All math is trusted Java code (calculate_requirement) — never the LLM.
2
DecideACCEPT, MODIFY, REJECT, or INVESTIGATE (needs a human).
3
ActApplication code (not the LLM) creates draft purchase orders.
4
ValidateAn independent validator re-checks: supplier minimum, supplier stock, budget, storage, stockout & overstock risk.
5
Self-correct or escalateFailed checks are fed back to the agent (max 3 attempts), then a human takes over.
6
Human approvalRisky plans wait for a person. Approving re-runs all checks in case the world changed.
