AI Purchasing Agent

Investigates a purchasing situation with tools, decides, acts, then validates its own result — exactly like a human buyer would.

What is this? How does the agent work?

This demo replaces a buyer at a quick-commerce company. The buying system suggests an order (e.g. "buy 800 units"), but the suggestion is not always right. The agent's job is to check it against real data and take action — safely.

  1. Investigate — the agent (an LLM) calls read-only tools: inventory, open purchase orders, supplier terms, budget, storage. All the math is done by trusted Java code (calculate_requirement), never by the LLM.
  2. Decide — it returns one of: ACCEPT (recommendation is right), MODIFY (change quantity/source), REJECT (don't buy), INVESTIGATE/ESCALATE (needs a human).
  3. Act — your Java code (not the LLM) creates draft purchase orders.
  4. Validate — an independent validator re-checks the drafted order: supplier minimum, supplier stock, budget, storage, stockout & overstock risk.
  5. Self-correct or escalate — if a check fails, the violations are fed back to the agent (up to 3 attempts), then it is escalated to a human.
  6. Human approval — risky plans (partial coverage, or value over 50,000) are held for a human. Approving re-runs all checks in case the world changed.
